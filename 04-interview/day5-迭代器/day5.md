1. 什么是迭代器？为什么容器需要迭代器？
迭代器是表示容器中某个位置的对象，并提供统一的访问和移动方式。它具有类似指针的操作，例如解引用和递增，但不一定是真正的指针，也不一定是智能指针。使用迭代器使得程序员能够更加方便的遍历访问容器，特别是针对map这些容器的遍历，这样更方便。
2. 为什么 STL 使用半开区间 [begin, end)？
begin 指向第一个元素；
end 指向最后一个元素之后的位置；
空容器时 begin == end；
元素数量可以用 distance(begin, end) 表示；
循环统一写成 it != end，不需要额外处理最后一个元素。

4. iterator、const_iterator、cbegin()、cend() 有什么区别？
iterator迭代器是可读可写的
const_iterator迭代器是可读不可写的
cbegin()、cend()都是const的，一个表示开始，一个表示结束。
const_iterator 中的 const 主要限制的是“不能通过迭代器修改元素”，不是说迭代器自己不能移动。
5. 为什么 vector 迭代器可以执行 it + 3，而 list 迭代器通常不可以？
vector 的迭代器支持随机访问，因此可以：
it + 3
it - 2
it[4]
it1 - it2
因为 vector 元素连续存储，可以直接计算地址。
list 的元素不连续，通常只支持：
++it
--it
如果想移动三个位置，只能连续递增三次。
6. vector.erase(it) 返回什么？删除后哪些迭代器会失效？
auto next = values.erase(it);
erase(it) 返回：
- 被删除元素后面的那个元素的迭代器；
- 如果删除的是最后一个元素，则返回 end()。
对于 vector：
被删除位置以及后面的迭代器、引用、指针会失效；
被删除位置之前的通常仍然有效。
和 const_iterator 没有关系，是否失效取决于容器结构变化，不取决于迭代器是不是 const_iterator。
7. vector.insert() 或扩容后，原来的迭代器什么时候可能失效？
也需要修正。
vector::insert 或扩容后：
- 如果发生重新分配，原来的所有迭代器、引用和指针都可能失效；
- 如果没有重新分配，插入位置及其后面的迭代器通常会失效；
- 插入位置之前的迭代器通常仍然有效。
其中重新分配是指：“重新分配”，指的是 vector 当前容量不够时，重新申请一块更大的连续内存。
8. rbegin()、rend() 和 begin()、end() 的关系是什么？
rbegin() -> 指向最后一个元素
rend()   -> 指向第一个元素之前的尾后位置
