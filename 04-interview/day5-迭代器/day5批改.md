# Day 5 批改与总结：迭代器

## 一、练习检查结果

### 1. `insert_sorted`

核心逻辑正确，能够处理：

- 插入到中间；
- 插入到开头；
- 插入到末尾；
- 空 `vector`。

当前测试输出符合预期。

复杂度：

- 查找插入位置：`O(n)`；
- `vector::insert` 移动元素：`O(n)`；
- 总体时间复杂度：`O(n)`。

代码中 `it = values.insert(it, value)` 的返回值可以接收，但因为随后立即 `return`，也可以直接插入后返回。

`main` 中仍有一个有符号/无符号比较警告：

```cpp
for (int i = 0; i < values.size(); i++)
```

可以改用 `std::size_t`，或者使用范围 `for`。

### 2. `remove_duplicates`

核心逻辑正确，能够正确处理连续重复元素：

```text
[1, 1, 2, 2, 2, 3, 5] -> [1, 2, 3, 5]
```

这段是关键：

```cpp
it = values.erase(it);
```

删除当前元素后，`erase` 返回下一个仍然有效的迭代器，因此删除分支不能再额外执行 `++it`。

当前实现的最坏时间复杂度是 `O(n^2)`：`vector` 中间删除元素时，后面的元素需要向左移动。后续学习 `<algorithm>` 时，可以对比 `std::unique` 的写法。

### 3. `reverse_copy`

逻辑正确，使用了反向迭代器：

```text
"levela" -> "alevel"
```

由于 `text` 是 `const std::string&`，`text.rbegin()` 返回的是只读反向迭代器，不能修改原字符串。

当前写法通过 `insert` 逐个插入字符，可以工作，但略复杂。更直接的思路是：

```text
先 reserve 原字符串长度
使用反向迭代器遍历
每次 push_back 当前字符
```

## 二、迭代器面试问题

### 1. 什么是迭代器？

迭代器是表示容器中某个位置的对象，并提供统一访问和移动元素的方式。

它具有类似指针的操作，例如：

```cpp
*it       // 访问元素
++it      // 移动到下一个位置
it == end // 判断是否到达尾后位置
```

迭代器不一定是真正的指针，也不一定是智能指针。它的价值是让不同容器可以使用相似的遍历方式。

### 2. 为什么使用半开区间 `[begin, end)`？

```text
begin -> 第一个元素
end   -> 最后一个元素之后的位置
```

好处包括：

- 空容器时 `begin == end`；
- 循环统一使用 `it != end`；
- 不需要单独处理最后一个元素；
- 元素数量可以用 `distance(begin, end)` 表示。

### 3. 为什么不能解引用 `end()`？

`end()` 不是最后一个元素，而是尾后位置的哨兵：

```cpp
*values.end(); // 未定义行为
```

正确访问最后一个元素应该使用：

```cpp
*(values.end() - 1)
```

但前提是容器非空。

### 4. `iterator`、`const_iterator`、`cbegin()`、`cend()`

```text
iterator       -> 通常可以读取和修改元素
const_iterator -> 可以读取，但不能通过它修改元素
cbegin()       -> 返回 const_iterator，指向第一个元素
cend()         -> 返回 const_iterator，指向尾后位置
```

`const_iterator` 中的 `const` 主要限制通过迭代器修改元素，不是说迭代器本身不能移动。

### 5. 为什么 `vector` 迭代器可以执行 `it + 3`？

`vector` 元素连续存储，迭代器是随机访问迭代器，可以支持：

```cpp
it + 3
it - 2
it[4]
it1 - it2
```

`list` 元素不连续，通常只支持双向移动：

```cpp
++it
--it
```

不能通过 `it + 3` 在常数时间内跳过三个节点。

### 6. `vector.erase(it)` 返回什么？

```cpp
auto next = values.erase(it);
```

返回被删除元素后面的新迭代器：

- 如果后面还有元素，返回下一个元素；
- 如果删除的是最后一个元素，返回 `end()`。

对于 `vector`，被删除位置以及后面的迭代器、引用和指针通常会失效；删除位置之前的通常仍然有效。

这和 `const_iterator` 没有关系，是否失效取决于容器结构是否发生变化。

### 7. `vector` 插入或扩容后为什么迭代器会失效？

当 `vector` 当前容量不够时，会发生重新分配：

1. 申请一块更大的连续内存；
2. 把旧元素复制或移动到新内存；
3. 释放旧内存；
4. 放入新元素。

示意：

```text
旧内存：[1, 2]       -> 释放
新内存：[1, 2, 3, ...]
```

原来的迭代器、指针和引用都指向旧内存，因此全部可能失效。

如果没有发生重新分配，通常只有插入位置及其后面的迭代器、引用和指针失效，插入位置之前的通常仍然有效。

可以使用 `reserve` 减少重新分配：

```cpp
values.reserve(100);
```

这只增加容量，不增加 `size`。

### 8. `rbegin()`、`rend()` 和 `begin()`、`end()`

```text
begin()  -> 第一个元素
end()    -> 尾后位置
rbegin() -> 最后一个元素
rend()   -> 第一个元素之前的位置
```

反向迭代器递增时，实际上向数组开头方向移动：

```cpp
for (auto it = text.rbegin(); it != text.rend(); ++it) {
    // 从最后一个字符遍历到第一个字符
}
```

## 三、今天的最终总结

```text
iterator       -> 容器位置的抽象
const_iterator -> 只读访问
begin/end      -> 正向半开区间
rbegin/rend    -> 反向半开区间
erase          -> 返回删除位置之后的新迭代器
insert         -> 可能移动元素并导致迭代器失效
reallocation   -> vector 容量不足时换一块更大的内存
```

今天已经掌握了迭代器的基本遍历、删除、插入和反向遍历。下一步进入 `list`、`deque`、`map` 等容器时，需要继续比较不同容器的迭代器能力和失效规则。
