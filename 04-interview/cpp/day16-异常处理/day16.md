1. throw、try、catch 分别有什么作用？为什么通常按 const std::exception& 捕获？
throw 用于抛出异常
try 不保证“代码继续执行”，而是将异常交给匹配的 catch；若没有匹配处理器，程序会终止。按 const std::exception& 捕获可避免复制/对象切片，并接住标准异常体系的派生类型。
catch是将异常捕获
2. 什么是栈展开？函数抛出异常时，局部对象会发生什么？
栈展开（stack unwinding）是异常从抛出点沿调用链向外层传播时，逐层退出函数作用域、寻找匹配的 catch 的过程。退出作用域时，已经构造完成的局部对象会按照与构造相反的顺序自动调用析构函数，即使退出是由异常导致的也一样，因此资源会被释放。
注意两点：① 若资源只由裸指针持有，销毁的只是指针本身，new 出来的堆内存不会释放（会泄漏），这正是需要 RAII/智能指针的原因；② 若展开过程中某个析构函数又抛出异常，两个异常同时存在，程序会调用 std::terminate() 直接终止。
3. RAII 为什么能保证异常发生时资源仍被释放？
RAII（Resource Acquisition Is Initialization）把资源的获取绑定到对象的构造，把资源的释放绑定到对象的析构。异常发生时会触发栈展开，局部对象必然自动析构，因此资源能够自动释放，不需要依赖 catch 中的手动清理代码；反之，用裸指针 + 手动 delete 时，异常路径会直接跳过 delete，无法保证释放。
这也解释了本日 Resource 类的作用：process(true) 抛出 runtime_error 后，s1、s2 仍在栈展开中被析构，静态计数归零——RAII 是能“亲眼验证”的。
4. 为什么析构函数通常不应该抛出异常？
析构函数除了在正常销毁时调用，也会在栈展开过程中被自动调用。若析构函数再次抛出异常：① 栈展开期间本就有异常在传播，两个异常并存，程序会直接调用 std::terminate()；② 容器（如 std::vector）批量析构元素时，某个元素析构抛出会导致其余元素不再析构，行为未定义；③ 收尾被中断，资源或状态不一致。
因此析构函数应保证不抛异常（C++11 起析构函数默认就是 noexcept）；若清理动作确实可能失败，应在析构内部捕获并记录，或提供显式的 close()/release() 让调用方在合适时机处理错误。
5. 什么是基本异常安全保证、强异常安全保证和不抛异常保证？
它们描述“函数抛出异常时对程序状态的承诺”，此外还有最差的“无保证”档（可能泄漏资源或留下损坏状态，应避免）：
基本异常安全保证：发生异常后，对象仍处于有效状态，没有资源泄漏，但对象状态可能已经改变。这是大多数函数应达到的底线。
强异常安全保证：发生异常后，操作要么完全成功，要么对象状态恢复到操作前，具有事务式的回滚效果。常用实现是 copy-and-swap：先在副本上完成所有可能失败的操作，成功后用 noexcept 的 swap 一次性替换原对象，失败则原对象不受影响。
不抛异常保证：操作保证不会抛出异常，通常用 noexcept 表示，是最强的承诺。典型代表是析构函数、swap、简单 getter——这类操作没有“可失败的中间状态”。
