面试题：
1. import data_utils 与 from data_utils import read_labels 分别会在当前命名空间中引入什么？各自有什么命名冲突风险？
import data_utils 只把模块对象绑定到当前命名空间的 data_utils 名称上，使用时写 data_utils.read_labels()。from data_utils import read_labels 则直接把函数绑定为当前的 read_labels，可直接调用。后者更容易和本地同名函数或变量冲突，也较难一眼看出函数来源；from xxx import * 的冲突风险更大。
2. if __name__ == "__main__": 解决什么问题？直接运行文件和被其他模块导入时，__name__ 各是什么值？
if __name__ == "__main__": 用于区分“当前文件被直接执行”与“当前文件被导入”。直接运行文件时，__name__ 是 "__main__"；作为模块导入时，通常是模块名，如 "data_utils"。因此测试、打印、读写文件等入口逻辑放在该判断中，导入模块时就不会意外执行。
3. Python 导入模块时会到哪些位置寻找？sys.path 与当前工作目录为什么可能导致“本机能运行，换目录就失败”？
Python 会优先使用已加载模块缓存，再通过导入机制在标准库、第三方包目录及 sys.path 中寻找模块。sys.path 通常包含脚本所在目录或当前工作目录、虚拟环境的 site-packages 等。若代码依赖“当前目录刚好能找到某个 .py 文件”，换一个启动目录就可能找不到模块，或者错误导入同名文件。解决方式是合理组织包、使用明确导入路径，并从项目规定的入口运行。
4. 包与普通目录有什么区别？__init__.py 的常见作用是什么？为什么不应在其中放沉重的训练或读写逻辑？
包是可通过点号导入的模块组织单位，例如 project.data_utils；普通目录只是文件夹。传统包通常包含 __init__.py，可用于包初始化、定义对外 API 或设置 __all__。Python 也支持没有 __init__.py 的命名空间包。因为导入包时会执行 __init__.py，不应放耗时训练、数据读取或大量写文件逻辑，否则一次普通导入也会产生昂贵副作用，甚至导致循环导入。
5. 虚拟环境解决了什么问题？为什么项目记录 Python 版本和依赖版本，而不是只说“我电脑上能跑”？
虚拟环境为每个项目隔离 Python 解释器和第三方依赖，避免项目间版本冲突，也避免误用系统环境中“碰巧已安装”的包。记录 Python 版本与依赖版本，才能让别人或未来的自己复现同样环境；否则“我电脑上能跑”无法说明实际依赖了哪个解释器、哪个库版本。当前练习只用标准库，requirements.txt 标注无第三方依赖是合理的。
